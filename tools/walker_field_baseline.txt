# walker_field_baseline.txt — generated + reviewed. See tools/audit_walker_fields.sh.
#
# Each line is `file:function:NODE_KIND:accessor`: a child field that a recursive
# kind-walker NAMES the kind of but never descends. Being in this file means the
# omission was looked at and judged correct; a NEW line fails `make check`.
#
# Two recurring, legitimate reasons appear throughout:
#
#   * STATEMENT-vs-EXPRESSION walkers. Many of these walkers only ever run on
#     expressions (or only on statements). The kinds from the other half are
#     listed in their exhaustive `switch` purely so `-Werror=switch` keeps
#     working, and have nothing to descend.
#
#   * NODE_ASM operands. `asm_stmt.inputs` / `asm_stmt.outputs` bind ZER lvalues,
#     and NO walker in the tree descends them. That is currently UNREACHABLE, not
#     safe: `asm` is legal only inside a `naked` function, and a naked function
#     may contain nothing but asm and `return` — so no local, no loop and no
#     effect can be reached through an operand. It becomes live the moment the S1
#     naked-only restriction is relaxed (Option E). Tracked in docs/limitations.md
#     as "asm operands are invisible to the AST safety walkers".
#
# 2026-08-26: 74 rows removed — the 45 for `register_decl` and the 29 for
# `zercheck_ir`. NEITHER FUNCTION IS RECURSIVE (both are called only from
# other functions), so neither was ever in this gate's stated scope
# ("recursive kind-walkers"). They were audited because the membership test
# counted the function NAME anywhere in the body text, comments and string
# literals included — so editing a comment moved a walker in or out of the
# audited set. The test now requires an actual CALL in comment-stripped
# code; see tools/audit_walker_fields.sh.
