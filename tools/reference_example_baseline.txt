# Each row is `<sha1-16 of the block body>  reference.md:<line when frozen>`: a
# ```zer example that does NOT compile standalone. Being in this file means the
# block was looked at and judged an intentional FRAGMENT — it names a type, a
# variable or a function that the surrounding prose supplies and that the

#
# THE POINT OF THE BASELINE IS TO SHRINK. Every row is an example a reader
# cannot paste into a file and compile. Converting one into a self-contained
# example and deleting its row is always an improvement; adding a row is a
# conscious admission. A NEW non-compiling block fails the build.
#
# The key is a hash of the block BODY, so the row survives the block moving in
# the file and dies the moment the block's text changes — which is exactly when
# it needs re-reviewing. The trailing `reference.md:<line>` is a human hint only.
#

# manufacturing its own failures, which is the false-confidence shape this repo
# gates against everywhere else, one level up. Fixed by making the Task-dependent
# prelude entries conditional on the prelude actually owning Task.
#
# THIRTY-FOUR blocks were converted into self-contained programs: the missing
# declaration added, or the block reshaped around a `main()` where a stub helper

# legitimate fragment and several remain so deliberately.
#
# Three of the conversions also removed a now-stale `<!-- audit: fragment -->`.
# That directive FORCES wrapping in main(), so once a block grows a top-level
# declaration the directive turns a working example into a failing one. If you
# make a fragment self-contained, delete its directive in the same edit.
#
# One conversion found a real DOC ERROR rather than a missing name: the
# documented `struct Task` had `[*]u8 name` and the example assigned a string

# mutable slice would hand out a writable view of it). The field is now
# `const [*]u8` and the rule is written into the NOTES. That is the audit doing
# its actual job — the doc asserted something the compiler does not allow.
